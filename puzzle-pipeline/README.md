# Puzzle Pipeline — 15×15 feasibility (updated)

**Question:** can we generate a *proper fully-checked* 15×15 crossword that
features SAT vocabulary, with pop-culture entries accepted as fill?

**Answer: yes — comfortably, and at series scale.** A single 15×15 fills in
1–3 seconds with a real crossword-quality wordlist. We ship a 27-puzzle run
(`output/`), each featuring a different SAT word, generated by
`seed_15.py`'s seed-and-discover approach. The earlier "impossible" finding
was wrong: it came from a tiny generic dictionary plus a slow solver, not
from any geometric limit.

## What changed

Two fixes turned an apparently infeasible problem into an easy one:

1. **Real crossword word list.** Replaced the 270k generic English dictionary
   with the [Crossword Nexus Collaborative Word List](https://github.com/Crossword-Nexus/collaborative-word-list)
   — a 567k scored wordlist of the kind professional constructors actually use,
   covering common words, proper nouns, and phrases. We keep entries with score
   >= 40 (332,624 entries) so the solver has room and `pick_15.py` picks the
   highest-scoring fill of many candidates.

2. **Solver speedup.** The forward-checking solver's per-node duplicate-word
   pruning was rebuilding the dedup'd domain set for every unassigned slot at
   every node — O(slots × |domain|) per assignment, which is huge on big pools.
   Replaced it with a single `used_ids` set checked when iterating
   candidates: ~45× faster (from ~1.5k nodes/sec to ~67k).

## Generated puzzle series

`output/` ships a **27-puzzle run** (`2026-05-22` → `2026-06-17`) covering
every SAT word whose length fits the standard template (26 of 30 — lengths
3,4,5,6,7,9,10 only; the template has no 8-letter slots so ELOQUENT /
DILIGENT / TENACITY / RESOLUTE sit out).

Each puzzle "features" a single seed SAT word (`seed_15.py`); whatever
additional SAT words bubble in naturally are kept. About a quarter of
puzzles end up with 2 SAT entries; the rest with 1.

### Why seed-and-discover beats force-five

The original `pick_15.py` pre-commits to **5 SAT words at fixed positions**.
That overconstrains the grid — non-synergistic word combinations crash the
solver, and the fill that does land is choppy (~27 weak entries, avg-score
~62). Worse: there's no way to control *which* 5 SAT words feature.

`seed_15.py` flips it. We pin **one** seed SAT word, then let the solver
discover the rest through:

- **Value ordering by SAT-ness.** SAT word IDs are 0..29 in the pool, fill
  IDs are 30..332k — so when iterating candidates for a slot, SAT words are
  already tried first wherever their letter constraints fit.
- **SAT-eligibility tie-breaker on MRV.** Among slots with the smallest
  domain, prefer one that still admits an unused SAT word, so the search
  commits SAT placements before chasing fill.
- **Many candidate solves per puzzle.** 8 independent attempts with
  randomized restarts; keep the one maximizing SAT count, then average
  fill score, then minimizing low-score entries.

Result on the same template: **avg-score ~69, weak fill ~18** — visibly
cleaner than the forced-five demo. And every puzzle features a *different*
SAT word as the headliner.

## Pipeline

| Step | File |
|---|---|
| Build the fill list | `build_fill_list.py` (xwordlist.dict → clean_fill.json) |
| Save a 15×15 grid template | `generator.py` `build_grid(15, ...)` → `data/template_15.json` |
| Forced-five themed fill (baseline) | `pick_15.py` |
| **Seed-and-discover series** | **`seed_15.py`** — one puzzle per SAT seed |
| Sweep grid sizes | `size_study.py` (legacy, smaller grids — see notes) |
| Validate | `validate.py` |

```bash
python3 build_fill_list.py
python3 seed_15.py --candidates 8 --time-budget 60   # generates ~26 puzzles
python3 validate.py output/2026-05-23.json
```

## What's still hard

- **Cluing 68 entries.** The artifact ships without clues — the production step
  is the handoff's `clue_writer.py` (Claude-backed). The app's
  `src/data/samplePuzzle.ts` continues to use a hand-clued freeform layout for
  this reason.
- **Eliminating *all* obscure fill** while keeping a fixed SAT theme on a fixed
  grid template is still genuinely hard; opening the score cut (40 vs 50) and
  using `pick_15.py`'s quality picker is the practical lever.

## Older finding (superseded)

A previous version of this study, using a 270k generic dictionary and the slow
solver, reported "5×5 / 6×6 only, 7×7 cliff." That conclusion was an artefact
of those tools — with a real crossword wordlist and the optimised solver, full
15×15 is the easy case.
